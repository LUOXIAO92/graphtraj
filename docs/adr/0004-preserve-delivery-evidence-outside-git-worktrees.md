# Preserve Delivery Run evidence outside Git worktrees

Delivery Run state must survive Ticket Worktree cleanup without entering
product history. It lives in a project-level persistent **Harness State
Directory** at `<harness-project-root>/state/`, outside the Source Repository
and every Git Worktree. The Integration Worktree exposes it through an ignored
`.scratch` symlink so Main and the Delivery State Agent retain the Matt Skills
scratch convention. The containing project boundary is defined in
[ADR 0012](0012-isolate-each-harness-project-at-its-own-root.md).

One run occupies `state/task-delivery/<run-id>/`. Its ledger is visible from
the Integration Worktree at
`.scratch/task-delivery/<run-id>/ledger.md`. Each ticket has exactly one
persistent evidence directory:

```text
state/task-delivery/<run-id>/tickets/<ticket-id>-<ticket-name>/
```

Retries and tier escalation reuse this directory rather than creating a
directory per Engineer session. When provisioning a Ticket Worktree, the
Runner creates a scoped `.scratch/task-delivery` symlink to that ticket
directory. Other Matt Skills scratch material remains local to the Ticket
Worktree.

Evidence ownership is divided by meaning:

- The Runner writes or updates `metadata.yml` with mechanically known launch
  facts such as run and ticket IDs, alias, role, Runtime session, branch, and
  worktree.
- Engineer developer instructions require the valuable semantic outputs: the
  current result, validation summary, and raw Standards and Spec Reviewer
  reports. Reviewer filenames include the session alias and review round so
  earlier evidence is not overwritten.
- The tracker binding supplies `ticket_id`; the Delivery State Agent supplies
  `run_id`; neither value is generated by the Engineer.

An Engineer returns either review evidence or a blocker. Review evidence
includes the candidate commit, validation summary, raw Reviewer reports, and
any outstanding concern; the Engineer does not claim review passed. A blocker
includes the blocker, evidence, attempted work, and the decision or condition
needed to continue. The Engineer does not repeat the DAG, tier, session,
worktree, or escalation counters already maintained by the Delivery State
Agent.

The Delivery State Agent reads evidence through the Integration Worktree's
persistent `.scratch` view and links it from the ledger instead of embedding
reports. Main reads it to adjudicate but does not repeat or rewrite it for the
state Agent.

Main may create Runner batch YAML in a temporary file. After validating it and
before launching an Engineer, the Runner preserves the exact input, including
any inline instruction, in the run's Harness State Directory and returns the
retained path. The temporary source may then be removed. The retained input,
ledger, Mermaid graph, Engineer results, validation evidence, and Reviewer
reports are never automatically deleted by ticket cleanup or run completion.
Only the operator removes persistent run state directly through the filesystem
or file manager; V1 exposes no Runner or product CLI command for it.

Raw Runtime event output and stderr are transport diagnostics, not delivery
evidence. They live with machine-local session mappings under
`<git-common-dir>/agent-runner/sessions/<alias>/` and are deleted with the
aliases and Ticket Worktree after successful cleanup. Canonical tickets or
tracker snapshots remain owned and retained by the tracker binding.

## Considered options

- Committing the ledger was rejected because live control-plane state should
  not pollute product history or participate in integration merges.
- Deleting batch inputs after launch was rejected because exact inputs aid
  tracing and recovery.
- Creating an evidence directory per Engineer session was rejected because the
  ticket is the durable unit of delivery while sessions are replaceable.
