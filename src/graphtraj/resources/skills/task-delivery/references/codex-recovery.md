# Codex recovery delivery

For an enforced stop, deliver its identity, trigger/send times, elapsed duration
and retained wrap-up through the actual parent's existing Runtime execution.
A log entry or later queue consumption does not demonstrate timely delivery.
Preserve native permissions and user Runtime settings; keep Codex-specific
transport behavior in its integration, while common task logic supplies events.

Follow the project's explicit authorization for recovery or a named retro using
the delivered evidence. Preserve explicit-only Skill discovery. Ordinary reminders
do not trigger a stop retro, and a delivery retry does not repeat an assessment
of the same event. Do not create another user message, parent Session or Driver
for recovery delivery. Continue through [recovery decisions](recovery.md).
