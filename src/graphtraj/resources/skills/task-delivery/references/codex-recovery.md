# Codex recovery delivery

When an enforced stop occurs, return its identity, real trigger/send instants,
separate elapsed duration and retained wrap-up through the original Main's
active Runner tool call. Keep the caller notice channel connected so Main can
handle the event before its long turn ends. Verify actual CLI and MCP delivery;
a log entry or eventual queue consumption does not establish timely handling.

The user has explicitly authorized automatic retro for these events. Main
executes that named Skill from the delivered evidence and makes the recovery
decision without another user confirmation. Preserve explicit-only discovery:
this is execution of the specified standing instruction, not permission to
select arbitrary Skills. Ordinary reminders do not invoke retro, and delivery
retries do not repeat analysis for the same stop.

Do not enqueue another user message or resume a second Main/Driver for this
automatic recovery. Preserve native Runtime permissions and configuration.
Keep Codex-specific details in Codex integration; common budget and Team logic
supply their ordinary events. Read the user's authorization clarification in
ADR 0039 (2026-09-17) and follow [recovery decisions](recovery.md).
