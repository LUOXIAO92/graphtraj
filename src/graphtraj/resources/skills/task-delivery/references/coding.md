# Selected coding-team method

Use this reference only when the project has selected coding coordination with
its configured Leader and members. Other coding tasks use their assigned roles
and validation responsibilities through the common task-delivery workflow.

Read the accepted Ticket, sources, investigation and reusable evidence. The
selected Leader assesses actual difficulty and scope, then assigns the needed
specialists and checks using the project's presets. Role names do not grant
control or acceptance authority; role_tree and real Session bindings apply.

Apply the project's test responsibilities. In a project that assigns test
acceptance to the Leader, reuse valid Engineer checks and run only still-needed
acceptance checks. Reviewers inspect code and retained evidence without running
project code, tests, builds, installs or probes. Main follows its assigned role.
Small fixes/test changes do not use TDD or code-review Skills; instruction-only
changes need consistency checking and a commit where tracked. For other work,
choose only necessary Review axes, each at most once per Ticket. Preserve those
reports for later correction verification.

Use the actual installed bootstrap. Candidate validation may use a separate
consistent installation without replacing the shared bootstrap. Keep retained
installations outside pytest numbered temporary directories. Give each member
its scoped files and inputs; preserve others' edits and project documents.

Formal dispatch uses the common swarm operation. Repository `skills` entries
must exist in the Worktree; read Harness Skills through their supplied paths.
When a child Batch returns `registered`, end the dispatch turn so the existing
Driver can start it. Keep one execution per Session and use actual returned
aliases, results and budget events. Apply the project's shared polling limit.

Members write assigned reports, commit file results and submit the exact
version. An authorized caller records the decision through `decide-result`.
The Leader returns its assessment to its actual parent. A code report, role
name or successful Session does not itself accept or complete a Ticket.

Use [budget handling](coding-budget.md) and [recovery](recovery.md) for control.
For an actual integration conflict, the authorized integrator selects a suitable
resolver through the existing integration operation. Preserve accepted inputs;
the project's assigned executor validates any changed behavior. Main integrates
only after the applicable acceptance, using the task's necessary validation.
